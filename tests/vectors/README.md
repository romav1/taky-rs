# Taky test vectors (T-03, format 2 since S-205)

Owner: an01. Consumers: qa01 (differential tests T-11/T-30), dev01/dev02 (unit/integration tests).
All Python expectations (`expect`) were **generated by running the original Python taky 0.9** and re-verified in check mode
(77/77 PASS: 56 CoT in both `exact` and `c14n`, 18 DPS, 3 unit vectors with 122 cases). `expect` is never edited by hand.
Rust expectations (`rust_expect`, see "Format 2") are hand-written in the builders from approved deviations D-n.

```
vectors/
  README.md                 — this file (format)
  cot/V001..V056.json       — CoT server: XML stream → deliveries, closes, persistence, mgmt, log_cot, cert-db
  dps/D001..D018.json       — DPS HTTP: request → response, files in upload_path, security (XXE, X-USER, hash traversal)
  unit/U001..U003.json      — unit: isoparse strings, float strings, taky.conf texts → Python result
  tools/build_vectors.py    — generator of INPUTS (+ rust_expect) for cot/*.json (source of truth for inputs)
  tools/build_dps_vectors.py— generator of INPUTS (+ rust_expect) for dps/*.json
  tools/build_unit_vectors.py — generator of INPUTS (+ rust_expect) for unit/*.json
  tools/run_python.py       — CoT runner against Python (reference oracle), modes check/--generate
  tools/run_python_dps.py   — DPS runner against Python (Flask test client)
  tools/run_python_unit.py  — unit runner against Python
  tools/vecfmt.py           — format-2 lint shared by the three runners (not a runner)
```
Workflow after changing inputs: `build_*.py` → `run_python*.py --generate` → check mode → review the diff
(expectations of untouched vectors must stay byte-identical).

## How to run against Python
```sh
python3 -m venv /tmp/venv && /tmp/venv/bin/pip install lxml cryptography dateutils python-dateutil 'Flask~=2.0' Werkzeug redis fakeredis gunicorn 'setuptools<80'
cd shared/spec/vectors
/tmp/venv/bin/python -W ignore tools/run_python.py      --taky-src ../../../taky cot/*.json   # PASS/FAIL per vector, exit 1 on FAIL
/tmp/venv/bin/python -W ignore tools/run_python_dps.py  --taky-src ../../../taky dps/*.json
/tmp/venv/bin/python -W ignore tools/run_python_unit.py --taky-src ../../../taky unit/*.json
# --compare c14n  — (CoT only) compare XML in canonical form (attribute order does not matter)
# --generate      — overwrite expect with observed behavior (only after a deliberate change of inputs)
```
Reference versions (S-205): Python 3.13.17, lxml 6.1.3 / libxml2 2.14.6, Flask 2.3.3, Werkzeug 3.1.9,
python-dateutil 3.0.0, cryptography 50.0.2, fakeredis 2.40.0 (recorded per vector in `verified_against`).
Check mode also runs the format-2 lint (`tools/vecfmt.py`); a lint error is a FAIL.
The runner does not modify `taky/` (it only imports it; `__pycache__` is not written). The CoT runner starts a **real** `COTServer` on 127.0.0.1 (TCP/TLS/unix sockets),
drives its `loop()` itself, freezes time (`datetime.utcnow`, `time.time` in taky modules) and emulates Redis via fakeredis.

## CoT vector format (`runner: "cot"`)
```jsonc
{
  "id": "V022",
  "title": "…",
  "runner": "cot",
  "tags": ["routing", "marti"],              // free-form tags: quirk, bug, libxml2-dependent, ssl, redis, mgmt …
  "source_refs": ["taky/taky/cot/router.py:155"],
  "notes": "",
  "now": "2030-01-01T00:00:00Z",             // frozen server UTC time at the start of the scenario
  "config": {                                // taky.conf overrides (section → key → string | null = key without a value)
    "taky": {"redis": "true", "hostname": "srv1"},
    "cot_server": {"max_persist_ttl": "60", "mon_ip": "127.0.0.1", "log_cot": "AUTO"},
    "ssl": {"enabled": "true"}
  },
  "clients": {                               // logical clients
    "A": {"kind": "cot"},                    // kind: cot | monitor
    "B": {"kind": "cot", "cert": "bob"},     // with SSL: client certificate with CN=bob (issued by the runner, added to cert-db)
    "B2": {"kind": "cot", "same_cert_as": "B"}
  },
  "revoked_before_start": ["mallory"],       // (opt.) CNs revoked in cert-db before the server starts
  "initial_redis": {"<key>": {"value": "<xml>", "ttl": 600}},   // (opt.) Redis pre-population
  "steps": [ { "op": "...", ..., "expect": {...} } ],
  "final_expect": { ... },
  "verified_against": "python taky 0.9 (tools/run_python.py)"
}
```
The runner fills in by itself: `bind_ip=127.0.0.1`, free `port`/`mon_port`, `root_dir`/`upload_path` in a temporary directory, `ssl.*` paths
(CA + server certificate with CN=localhost are generated on every run, p12 password `atakatak`), `log_cot: "AUTO"` → temporary directory.

### Operations (`steps[].op`)
| op | Fields | Action |
|---|---|---|
| `connect` | `client` | TCP connection to the CoT port (or the monitor port for `kind: monitor`); with SSL, a TLS handshake with the client certificate. Deliveries on connect (persist replay) are observed. |
| `send` | `client`, `chunks` (array of UTF-8 strings) **or** `chunks_b64` (array of base64) | Each chunk is sent separately, and the server processes input after each one (chunk boundaries = server `recv` boundaries). |
| `close` | `client` | The client closes the socket. |
| `advance` | `seconds` | Advance the frozen time (prune/stale fire). |
| `mgmt` | `request` (object → `json.dumps`, or a raw string) | Connect to the mgmt socket, send `request + "\0"`, read the response up to `\0`, disconnect. |
| `mgmt_hold` / `mgmt_release` | — | Open a mgmt connection and hold it (send nothing) / close all held ones. |
| `mgmt_multi` (f2) | `requests` (array) | One mgmt connection, all requests framed back-to-back (`…\0…\0`); `mgmt_response` is the array of responses. |
| `connect_raw` (f2) | `client` | Plain TCP connect to the CoT port without a TLS handshake (handshake-timeout tests). |
| `issue_cert` (f2) | `cn` | Emulates `takyctl build_client` while the server runs: a new client certificate with this CN is appended to cert-db by another writer. |

`chunks` (f2) may also contain `{"prefix": str, "repeat": str, "count": int, "suffix": str}` = `prefix + repeat*count + suffix`
(large inputs, e.g. D-2 limits, without bloating the file).

### Step expectations (`steps[].expect`)
| Field | Meaning |
|---|---|
| `deliveries` | `{client: [xml, …]}` — everything the client received from the server during this step, split into events, **in order of receipt** (except `connect`: multiset, see Format 2). Client not listed ⇒ received nothing (checked after settle, see Format 2). The wire stream = concatenation of the strings with no separators. |
| `server_closed` | list of clients whose connection the **server** closed during this step (EOF/RST). |
| `mgmt_response` | parsed mgmt JSON response (`{"_no_response": true}` — there was no response). `"$SERIAL_INT:<cn>"` — serial of the certificate with this CN, as an integer. |
| `persist` | persistence snapshot after the step (see below) — only where explicitly recorded. |
| `server_crash: true` | the server process would crash (unhandled exception in `loop()` → exit 1); `server_crash_reason` is informational. Subsequent steps are not executed by the Python runner (they are Rust-only, see Format 2). |

### `final_expect`
| Field | Meaning |
|---|---|
| `persist` | `{"backend": "memory", "uids": [...]}` (internal state; for Rust — via a test hook or indirectly via replay) or `{"backend": "redis", "keys": {key: {"value": str, "ttl": int}}}` — **exact Redis contents** (keyspace/value format/TTL are normative, ADR-000). |
| `log_files` | `{file_name: content}` of the `log_cot` directory; `$IP` = client IP; the comment in `<__taky_err>` is normalized to `<!--$ERROR_TEXT-->`. |
| `cert_db_status` | `{CN: "V"|"R"}` from `cert-db.txt` after the scenario. |

### Comparison
- `exact` (default, target mode for Rust): XML strings match byte-for-byte (attribute order, ASCII + `&#N;`, number/time format).
- `c14n`: XML is compared after C14N (allows a different attribute order/quotes). If arch01 decides byte-exact matching is not required, qa01 uses this mode.
- Delivery order across **different** clients is not checked (only the order within a single client).
- Redis `ttl` tolerance and `connect` replay as a multiset: see Format 2 below.

## DPS vector format (`runner: "dps"`)
```jsonc
{
  "id": "D004", "runner": "dps", "title": "…", "source_refs": [...],
  "config": {"taky": {"hostname": "taky.example"}, "ssl": {"enabled": "true"}},  // upload_path is filled in by the runner
  "base_url": "https://taky.example:8443/",        // (opt.) request scheme/Host, default as shown here
  "initial_files": {"meta/h1.json": {"symlink_to": "U1_pkg.zip.json"}, "U1_pkg.zip": {"content": "DATA"}},  // relative to upload_path
  "steps": [{
    "request": {"method": "POST", "path": "/Marti/sync/missionupload",
                "identity": {"cn": "alice", "revoked": false},   // null = no client certificate
                "query": {"hash": "…"}, "headers": {}, "body": "…",
                "multipart": [{"name": "assetfile", "filename": "a.zip", "content_type": "application/zip", "data": "…" /* or data_b64 */}]},
    "record_headers": ["Content-Disposition"],      // (opt.) which headers to record into expect.headers
    "expect": {"status": 200, "content_type": "text/html; charset=utf-8",
               "body": "…" | "body_json": {...} | "body_b64": "…" | "body_is_framework_page": true,
               "headers": {"Content-Disposition": "…"}}
  }],
  "final_expect": {"files": {"<rel path>": {"content": "…"} | {"content_b64": "…"} | {"symlink_to": "…"}}}
}
```
- `identity`: the Python runner turns it into `X-USER`/`X-REVOKED` headers (set by the gunicorn worker from the TLS certificate). **The Rust runner must present a real client certificate** with this CN (and an `R` line in cert-db for `revoked`).
- Normalization: `SubmissionDateTime` → `"$TIMESTAMP"` (in JSON responses and meta files); `taky-<version>` → `taky-$VERSION`; the absolute upload_path in the body → `$UPLOAD_PATH`.
- `body_is_framework_page: true` — the body is a Flask/Werkzeug HTML error page; only the status is checked.
- `content_type` is compared exactly.

## Format 2 (S-205)
Additive over format 1: a consumer that ignores the new fields still runs the Python expectations correctly.

### Vector-level fields
| Field | Written by | Meaning |
|---|---|---|
| `format` | generator | `2`. |
| `requires` | generator | Capabilities needed to run the vector against a **live** binary (black-box difftest without time freezing): `clock` (conservative: an `advance`, `max_persist_ttl`, Redis TTLs, mgmt `status`, an input `stale` ≤ `now`, or an expected time/start/stale that does not occur in the inputs, e.g. takPong), `tls`, `redis`, `mgmt`, `log_cot`, `persist-hook` (a memory `persist` expectation — Rust: test hook `Router::persist_snapshot()`; a black-box runner without the hook skips only those checks), `certgen` (`issue_cert`), `remote-addr` (DPS). |
| `verified_against` | generator | `{"oracle": …, "versions": [python, lxml, libxml2, python-dateutil, cryptography, fakeredis, Flask, Werkzeug, …]}`. |
| `expected-divergence` | builder (by hand) | `["D-n", …]` — approved deviations (compat-matrix §2) implemented by this vector's `rust_expect`. Present ⇔ the vector has at least one `rust_expect` / `final_rust_expect` (lint). |
| `final_rust_expect` | builder (by hand) | Replaces `final_expect` **entirely** for Rust runners. Absent ⇒ Rust uses `final_expect`. |

### Step / case-level fields
| Field | Meaning |
|---|---|
| `steps[i].rust_expect` (cot, dps), `cases[i].rust_expect` (unit) | Replaces `expect` of this step/case **entirely** for Rust runners (same schema). Absent ⇒ Rust uses `expect`. |
| Rust-only steps | Steps after a step whose `expect.server_crash` is true are not executed by the Python runner and have no `expect`, only `rust_expect` (V013 step 3, V051 step 2: the Rust server is still alive). |

Rust runner rule: `exp = step.rust_expect ?? step.expect`, `final = vec.final_rust_expect ?? vec.final_expect`.
The Python runners never execute `rust_expect`; they lint it (`vecfmt.py`: `format == 2`; `rust_expect` ⇔ `expected-divergence`;
every D-n exists in compat-matrix.md; `rust_expect != expect`). The hand-written CoT `rust_expect` were cross-checked against Python
with the D-n fixes monkey-patched in (`an01/work/probes/rust_expect_probe.py`, 4/4 PASS).

### Comparison rules added in format 2
1. **Replay is a multiset.** Deliveries observed in a `connect` step (persist replay) are compared order-insensitively; the replay order
   is not normative (CS §9.3; Redis `KEYS`/`SCAN` order is arbitrary). All other steps keep per-client order.
2. **Redis TTL tolerance.** `persist.keys[k].ttl` matches if `expect − 1 ≤ observed ≤ expect` (a real redis-server counts down while the
   test runs; fakeredis with the frozen clock gives exactly `expect`). `value` stays byte-exact.
3. **Settle.** A step's observations (deliveries, `server_closed`, "client not listed ⇒ received nothing") are taken only after the server
   has processed all input of the step and flushed its output (Python runner: `pump()` until idle; Rust: test barrier `Hub::settle()`).
4. **Memory persist** is observed via a test hook (`Router::persist_snapshot()`, testkit feature), `uids` sorted.
5. **DPS identity** ⇒ a real client certificate over TLS; with `ssl.enabled=false` the Rust runner sends the headers as is (until G-6).
6. XML and Redis values: `exact` is normative (arch01, compat-matrix §4); `c14n` is diagnostics only.

### Unit vector format (`runner: "unit"`)
`{"id", "runner": "unit", "kind": "isoparse"|"float"|"ini", "cases": [{"input": str|null, "keys": [...] (ini only), "expect": {...}, "rust_expect"?: {...}, "note"?}]}`.
`isoparse`: `{"ok": naive isoformat with µs, "cot": wire form}` or `{"error": "UnmarshalError"|"OtherException", "python_exception"}`;
`float`: `{"ok": repr, "f6": "%.6f", "f1": "%.1f"}` or an error; `ini`: `{"values": {"sect.key": value}}` or
`{"error", "taky_exit", "taky_output": "config_error_message"|"traceback"|"message"|"argparse_error"}`.
